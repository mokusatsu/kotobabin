## 1. 検証方法

仕様の節目ごとに新規の独立エージェントを起動し、会話履歴と前段のレビュー結果を渡さずに評価した。
レビュー担当へ渡したものは、その段階の対象仕様、必要に応じた出題データ・代表画像と、sakurai-skillの本体・必要な同梱資料の参照先だけである。
第1〜第2版のレビューでは外部Web検索、他スキルの参照、他の仕様草稿の閲覧、再委任を禁止した。第3版でも評価基準の資料をsakurai-skillに限定し、過去の稿やレビュー結果を参照対象に含めていない。
判定基準の適用では、アクションゲーム向けの表現をタイピングへ機械的に転用しないよう求めた。

技術資料の事実確認は別の調査担当と作成担当が実施し、独立したゲームレビューの評価基準には加えていない。
本記録は文書の検証であり、実装済みのゲーム、実機性能、ユーザーテストの結果を証明するものではない。

## 2. 第1節目 企画と遊びの核

- 担当: 独立レビュー担当A
- 対象: 企画仕様 v0.1、全8節
- 判定: 必須修正2件、推奨2件。核は成立。

### R1-01 必須 配達の可否と画面案内の不一致

- 問題: 次の語を打ち始めた後も「Spaceで届ける」が残る実装が可能だった。
- 根拠: 原則1・4・9、gameplay #006、planning #104。
- 修正: 荷物1〜4個かつ語境界の時だけ配達案内を出す。入力中は完成を促す表示へ切り替える。
  次の語に挑む際、現在の追加点と、誤打でその追加点を失うことを先に示す。
- 状態: 反映済み。本文4.1節、8節。

### R1-02 必須 チュートリアルの誤打後に配達できない

- 問題: 最初の語で誤打すると荷物が得られず、固定された配達手順に進めない。
- 根拠: 原則2・4、gameplay #116、planning #085・#240。
- 修正: 指定語の終了ではなく荷物状態で進行を判定する。失敗後は次の短い語へ進み、途中から積み直す。
  1個の配達も祝い、全体のやり直しを要求しない。スキップを常設する。
- 状態: 反映済み。本文3節。

### R1-03 推奨 選択の検証を具体化

- 問題: 1回配達しただけでは、次の語への自信に応じた使い分けを確かめられない。
- 根拠: 原則1、gameplay #006・#146。
- 修正: 追加点のリスクの理解と、手動配達・続行の使い分けを初見観察の基準にした。
  熟練者が常に5個を狙う自然な攻略は妨げない。
- 状態: 反映済み。本文4.3節、12節。

### R1-04 推奨 小さな完成にも報酬を返す

- 問題: 5個の配達以外、とくに誤打を含む語の完成を祝う反応が薄かった。
- 根拠: 原則3、planning #095・#198。
- 修正: 誤打の有無にかかわらず完成点・小さな灯り・完成音を返し、1個の配達にも街の反応を付ける。
- 状態: 反映済み。本文9節。

### 第1レビューが妥当とした主な設計

- 確定得点と入力済み文字を失わない罰の範囲。
- 演出の静止を荷物だけに使い、打鍵を止めないこと。
- 得点と街の変化を報酬とし、通貨や恒久強化を無理に追加しないこと。
- 共通ルールの3コース、PCの物理キーボード、ログインなしという初版範囲。

## 3. 第2節目 ルールと入力と画面

- 担当: 独立レビュー担当B
- 対象: 詳細仕様 v0.5、全12節
- 判定: 必須修正3件、軽微な明確化1件。骨格の組み替えは不要。

### R2-01 必須 スキップ時の正確率の分子と分母

- 問題: スキップした語を分母からだけ除外すると、正確率が100%を超える解釈が成立する。
- 根拠: 原則3・9、planning #198。
- 修正: スキップ操作自体を採点せず、その前に実際に打った正解・誤打は双方とも集計に残す。
  指摘の「双方から除外」案に対し、実際の入力履歴を保持する方式で分子と分母を統一した。
- 状態: 反映済み。本文4.3節、11節、17節の例。

### R2-02 必須 開始と再開のフォーカス復帰

- 問題: 再開ボタンにフォーカスが残ったまま、タイマーだけが動く実装が可能だった。
- 根拠: 原則2・4・5、planning #104、gameplay #116。
- 修正: 初回・再挑戦・練習開始・再開で入力要素へフォーカスを移し、成功後に入力と時間を有効化する。
  フォーカスが戻らない場合は待機または停止を維持する。
- 状態: 反映済み。本文3節、10節、17節。

### R2-03 必須 途中でガイドを表示した回の記録区分

- 問題: ガイドOFFで始め、苦手な語だけ表示してからOFFへ戻した回の比較条件が曖昧だった。
- 根拠: 原則3・9、planning #198、ui #252。
- 修正: その回に一度でも表示したかを記録する。後でOFFにしても「ガイド表示あり」の区分を戻さない。
- 状態: 反映済み。本文11節、14.3節、17節。

### R2-04 軽微 未完成語の復習条件

- 問題: 終了時の未完成語を復習候補にする説明と、誤打した語だけを選ぶ規則の関係が不明瞭だった。
- 根拠: 原則9、ui #227。
- 修正: 未完成語も、誤打がある場合は候補に含めると明記した。
- 状態: 反映済み。本文10節、11節。

### 第2レビューが妥当とした主な設計

- 点数例、荷物の意味、確定点の保護。
- 複数経路を保つローマ字入力と、語末んをnn等で確定する方針。
- 3コースと240件の題材計画。
- 誤打から復帰できる導入、入力を止めない演出、同じ順への素早い再挑戦。

## 4. 第3節目 完成稿

- 担当: 独立レビュー担当C
- 対象: 完成稿 v0.8、全19節
- 判定: 必須修正1件、推奨1件。主要な設計は一貫。

### R3-01 必須 練習開始とREADYからの停止復帰

- 問題: 状態表にHOMEからPRACTICEへの経路と、READYで停止・入力再確認した後の復帰先が不足していた。
- 根拠: 原則2・4・9。
- 修正: 開始先を保持するlaunchTargetと、停止前の状態を保持する経路を明記した。
  READYへ戻った時はフォーカス復帰後も時計を進めず、最初の採点対象キーまで残り90秒を維持する。
  ホームからの練習開始とREADYからのIME再確認を受入試験へ追加した。
- 状態: 反映済み。本文14.1節、17節。

### R3-02 推奨 ガイドOFF時の次語予告

- 問題: 次の語のローマ字例を無条件に表示する記述が、ガイドOFFの設定と衝突する解釈を残していた。
- 根拠: 原則3・9。
- 修正: 日本語・読み・成功時のボーナスを常時予告し、ローマ字例はガイドONの時だけ表示する。
- 状態: 反映済み。本文4.1節、17節。

### 第3レビューが一貫していると確認した主な設計

- 完成点、荷物の追加点、誤打、スキップ、正確率の関係。
- 複数経路の入力判定と、同じグラフから求める基準長。
- 進行中のIME再確認で同じセッションを保つこと。
- ガイド使用履歴を保持する記録、誤打した語の復習。
- 入力を止めない配達演出と、失敗後の再挑戦。

## 5. 第4節目 最終確認

- 担当: 独立レビュー担当D
- 対象: 修正を統合した仕様 v1.0、全19節
- 判定: 必須修正0件、推奨1件。設計レビューとして承認可能。

### R4-01 推奨 状態表と本文の導線をそろえる

- 問題: 本文には、結果からコース選択へ戻る操作と、操作体験から練習へ進む操作があるが、
  状態表のRESULT行とTUTORIAL行に列挙されていなかった。
- 根拠: planning #104。本文で目的の操作と行き先を判断できるため、必須修正ではない。
- 修正: RESULT行へコース選択とHOME、TUTORIAL行へ練習移行とPRACTICEを追記した。
- 状態: 反映済み。本文14.1節。

### 第4レビューの結論

- 遊びの核、報酬、誤打後の続行、入力説明、初見体験に重大な仕様矛盾は認められない。
- 通常の開始、停止、IME再確認、終了、再挑戦、練習終了を本文から追える。
- 必須修正0件の判定は、ゲーム設計の整合性と実装開始の準備に対するもの。
- 実装の動作、実機性能、実際の面白さの合格を意味しない。

最終推奨1件は本文で既に定めた導線の表記補完であり、ゲームの規則・得点は変更していない。

## 6. 作成担当による整合確認

入力規則を模した一時的な参照モデルで、本文の43通りの正解経路、3通りの未完了または不正経路、
基準長、ボーナス表、得点例を検証した。全ケースが記載の結果と一致した。
これは仕様例の整合検証であり、製品の入力エンジンやブラウザー上の動作試験ではない。

本文では、実装後に必要な入力・終了境界・IME・一時停止・保存失敗等の受入試験と、
初見の対象者による観察基準を別に定義した。未実施の試験を合格済みとは扱わない。

WordからPDFへ変換し、全24ページの文字、表、画面図、改ページを目視確認した。
本文の参照資料にはリンクを付け、仕様とレビュー記録の未確定表示が残っていないことを確認した。

## 7. 第2版 資料分離と実績体験の拡充

[ゲーム体験仕様書](game_experience.md)と[技術仕様書](technical_specification.md)を独立した資料に分けた。
ゲーム体験には48実績、発見、選択、進捗、解除、通知、報酬、履歴、図鑑、練習から本編への導線を追加した。
技術仕様には実績の計測、確定、重複排除、保存、通知、条件改版、旧記録移行を接続した。
本章の文書レビューも毎回、新規独立担当に対象稿とsakurai-skillだけを渡し、会話履歴と前段レビューを渡していない。
ブラウザー技術の一次資料確認と組版確認は、ゲーム設計の独立レビューとは別に実施した。

### 7.1 第2版の第1節目 実績体験の企画

- 担当: 独立レビュー担当E
- 対象: 第2版企画確認稿の全11節、A〜Hの全48実績
- 判定: 必須修正2件、推奨5件。配達の核と実績のつながりは成立。

#### R5-01 必須 補助機能の方針とガイド非表示実績

- 問題: 補助機能を無効化させないという一般方針とH05のガイド非表示条件が食い違っていた。
- 根拠: planning #149、ui #227。
- 修正: 音・文字拡大・動き軽減等は利用可能とし、H05だけをガイド非表示の任意の熟練目標として明記。
- 状態: ゲーム体験3節・5節・H05・8.2節へ反映。

#### R5-02 必須 仮達成が解除を保証する表示

- 問題: 正確率等は途中で条件内でも、その後に外れるため「完走で切手」と一律に言えない。
- 根拠: planning #023、ui #227。
- 修正: 成立済みの配達・連続記録と、終了まで維持する正確率・ガイド条件を分ける。
  維持条件は「現在は条件内。終了時に判定」と表示し、今回の状態に応じて更新する。
- 状態: ゲーム体験5節・5.1節・10.1節と、技術の仮達成契約へ反映。

#### R5-03 推奨 無誤打条件による待機の誘導

- 問題: 20語等に到達した後、入力しない方が便全体の無誤打を守りやすくなる。
- 根拠: planning #248・#149。
- 修正: C06を20語連続、H02を30語連続の無誤打完成へ変更。
  便内で成立した最長連続記録を保持し、その後の誤打で失わない。通常の便の完走で確定する。
- 状態: ゲーム体験5節・C06・H02へ反映。観察項目にも目標後の待機を追加。

#### R5-04 推奨 配達回数が小分け発送を優遇

- 問題: 同じ5語でも1個ずつ配達した方が累積実績を5倍速く進められた。
- 根拠: gameplay #006・#075、planning #149。
- 修正: G04・G05を届けた荷物の累計50個・250個へ変更。1個なら1、5個なら5と数える。
- 状態: ゲーム体験5節・G04・G05と、技術の配達事実契約へ反映。

#### R5-05 推奨 誤打時の荷物状態

- 問題: 追加点を失った後に、荷物の個数も空になるかが企画稿の本文では省略されていた。
- 根拠: gameplay #006。
- 修正: 誤打で荷物を空にし、その語は荷物にせず、次の語から積み直すと明記。
- 状態: ゲーム体験2節へ反映。完成点と入力済み文字は保持。

#### R5-06 推奨 最初の実績の名称

- 問題: 「はじめの一文字」は1打で達成するように読めるが、条件は語の完成だった。
- 根拠: planning #085、ui #227。
- 修正: A01を「はじめのことば」へ変更。
- 状態: 名称、導入文、切手と称号の扱いへ反映。

#### R5-07 推奨 初回配達の観察方法

- 問題: 自動配達だけでも最初の配達の時間目標を満たせるため、手動配達を理解したか判断しづらい。
- 根拠: planning #017・#085、gameplay #006。
- 修正: 初回配達が手動か自動かと、語境界でSpaceと続行を選べたかを分けて記録する。
- 状態: ゲーム体験10節へ反映。

### 7.2 第2版の第2節目 ゲーム体験の完成稿

- 担当: 独立レビュー担当F
- 対象: 第2版ゲーム体験完成稿の全11節、全48実績
- 判定: 必須修正0件、推奨2件。文書上はゲーム体験の実装を開始可能。

#### R6-01 推奨 精度目標達成後の待機を早期に観察

- 問題: C01等では途中で条件を満たした後、正確率を保つために待つ選択が合理的になりうる。

- 根拠: planning #248・#149。
- 修正: C01を含む12件の試作段階で、配達の使い分けと条件到達後の入力継続を初見観察する。
  待機が主要行動となる場合は精度条件と進捗表示を調整し、再観察する。
- 状態: ゲーム体験10.2節へ反映。数値条件の適切さを実証したという意味ではない。

#### R6-02 推奨 G05カードの自己完結性

- 問題: 「同じ対象の配達」は直前のG04を読まないと対象が分からない。
- 根拠: ui #227、planning #023。
- 修正: 「手動配達と5個の自動配達で届けた荷物が累計250個」と明記。
- 状態: ゲーム体験G05へ反映。計測方法の変更はない。

#### R7-01 推奨 完成した語数と配達した荷物数の表現
