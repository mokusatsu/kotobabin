# ことば便 資材の実装・合成仕様

版4.1　2026年11月13日

資材IDをゲーム状態へ対応させ、数値・状態・図柄を分離して描画する。本書は画像の合成と書き出しの技術資料であり、解除条件・育成条件は[実績](achievement_catalog.md)、[街](city_development_catalog.md)、[設備](equipment_catalog.md)に分ける。ローマ字・IME・採点・保存の契約は[技術仕様書](technical_specification.md)を参照する。

## 1 正本と資材の引き方

| 正本 | 役割 |
|---|---|
| achievement_catalog.json | 全72実績と追加40報酬。条件・進捗・確定・保持・切手・称号 |
| city_catalog.json | 36地区段階、景観3、画像の位置、固定6路線 |
| equipment_catalog.json | 全所有レベルの価格・性能・外観帯、鉄道・連携・研究 |
| rendering_rules.json | 合法な表示状態と同時表示、動き軽減、装飾選択 |
| visual_resource_manifest.json | 248制作資材、寸法型、使用画面、逆参照709件、出力形式 |

参照は「ゲーム項目ID→asset_refs→資材ID→仕様型と出力先」の順で解決する。資材IDとゲーム項目IDを同一視しない。例えば荷づくりレベル9は`equipment_packaging_1`、10は`equipment_packaging_2`を参照し、倍率はそれぞれ3.25倍と7倍のDOMで表示する。同じ画像を別画面に置いても制作点数は増えない。使用画面の一覧は全資材のplacementsから再生成し、台帳には本編・練習・導入で使う絵も記載する。

SVGの寸法は各資材行のviewBoxを使い、型の相対余白を適用する。寸法型のレイヤーは基準であり、資材ごとのrender_layerが最優先となる。足場3点はscaffold、店舗の追加3点はshop_overlayへ置く。PNG原画は外周を勝手にトリミングせず、基準点を固定する。WebPは原画と同じ寸法・アルファを保持し、表示倍率はCSSで調整する。低彩度・未解除・hover・ピン付きなどの派生PNGは作らない。

6切手を載せる詳細台紙は600×400CSS px以上を確保する。1200×800の台紙上で、切手枠240×240の中心をx=200/600/1000、y=220/570へ配置する。最小台紙では枠120×120、内側の絵96×96となり、枠90×90・絵72×72の下限を満たす。名前は16CSS px・行高20CSS px・最大2行・幅336source_px以内で、元座標y=350/700を行ボックスの上端、各列中心を横中央として置く。紋章64×64source_pxは(96,56)中心、見出しは左端x=160・縦中央y=56を基準に置き（left_center、描画位置から行ボックスの高さの半分だけ上へ移す）、見出しの文字は24CSS px以下・行高32CSS pxとする。名称を16CSS pxより拡大する場合は固定台紙の6枚配置を使わず、2列/1列のDOMカードへ切り替えて行高と高さを広げる。台紙の内窓は(32,96)〜(1168,784)を透過に保つ。紙→共通台紙→紋章→切手原画→切手枠→外周の箔→実績名→選択とフォーカスの順に合成する。固定台紙の6枠は絵・枠・実績名だけに限定し、条件、進捗、獲得日、「獲得／未解除／完走で確定」などの状態文、目標や未読の操作は台紙の外の選択詳細欄へ置く。通常の配達手帳の実績カードは、条件や状態文を含む可変高のDOMで別に構成し、固定台紙の寸法へ押し込まない。240×160CSS px以上の小さい台紙サムネイルには紋章と完成状態だけを表示し、詳細を開いた際は規定寸法か1列/2列のDOMカード一覧へ切り替える。

報酬の額縁は1200×800のうち(96,96)〜(1104,704)を透過の内窓とし、葉・敷石・雲・地図の飾りを内窓へ入れない。内側の鑑賞画はcontainで収め、面→鑑賞画→額縁→文字→状態とフォーカスの順に合成する。

### 固定6路線

路線は次表の折れ線からSVGで描く。未開通は破線、開通後は道路、貨物鉄道購入後は2本のレールとまくら木へ切り替える。本線は傾き±1/2なので、正面寄り・背面寄りの原画と左右反転で車両の4方向を表せる。無反転frontは(+2,+1)の右下、無反転rearは(+2,−1)の右上を向く。水平反転でそれぞれ左下と左上を作り、線分の角で向きを切り替える。端点の最大5pxの接続は積み下ろし場の下に隠し、別方向の原画を要求しない。

| 基本状態 | 表示 | 共通資材 |
|---|---|---|
| 未解除 | 固有絵を低彩度・薄い紙色へ寄せ、未解除ラベルを併記。透明度だけで文字を薄くしない。 | `stamp_frame` |
| 完走で確定 | 未解除の絵＋進捗枠。達成した切手としては数えない。条件維持型は終了時判定と表示。 | `stamp_frame` |
| 獲得 | 固有絵を彩色で表示し、チェックと獲得日を別DOMで置く。 | `stamp_frame`、`ui_check` |
| 今回は対象外 | 通常資格を失った現在の便の目標に短文を表示。過去の獲得状態を上書きしない。 | `ui_info` |

| 独立した印 | 意味と配置 | 共通資材 |
|---|---|---|
| 詳細を表示中 | 外周2pxの選択枠。獲得済み/未解除と共存。 | 専用画像なし（DOM） |
| 今回の目標 | 左上のピン。選択枠の有無とは独立。達成後も本人が変更するまで保持。 | `ui_pin` |
| まだ見ていない獲得 | 右上に封筒印。獲得済みだけに付く。 | `ui_unread` |

未解除は同じ原画を低彩度でプレビューし、線画専用の画像を生成しない。B05・F06の未公開状態は固有図と名称を隠し、共通の封筒印とヒントを置く。条件を見る操作に不利益はなく、獲得時は必ず固有図を公開する。

| 不正な組み合わせ | 実装での扱い |
|---|---|
| 未解除＋未読獲得 | 許可しない。未読は獲得済みだけ |
| 仮達成＋獲得数への加算 | 許可しない。通常の便を完走してから確定 |
| 隠し未公開＋獲得済み | 獲得時に公開状態へ変える |
| 選択中＋目標固定 | 許可。選択枠とピンは別表示 |
| 今回は対象外＋過去の獲得 | 併存できる。現在の便の注記で、獲得を取り消さない |
| 装飾のプレビュー＋装着済み扱い | 確定前に装着しない。プレビュー枠と装着中ラベルを分ける |

称号・額縁・飾り・背景は、それぞれ1つまたは非表示を選べる。アルバムと記念台紙は鑑賞物で、専用の装備スロットを必要としない。系統の6件達成後はその台紙の箔を自動適用するが、称号と額縁を勝手に切り替えない。

## 5 地区と設備の状態合成

| 地区状態 | 許可する段階 | 表示 | 共通資材 |
|---|---|---|---|
| 未開通 | 0 | 共通更地＋地区アイコン＋鍵。路線は薄い破線。開通条件はDOM。住宅地にはこの状態を適用しない。 | `city_plot_empty`、`ui_lock` |
| 開通・計画なし | 0／1／2／3／4 | 段階0は更地、1以上は現在段階画。路線は道路または購入済み貨物鉄道。 | 専用画像なし（DOM） |
| 建築中 | 0／1／2／3／4 | 現在段階画＋次の段階に対応する足場。進捗バーと積立値はDOM。 | `ui_plan` |
| 計画停止中 | 0／1／2／3／4 | 同じ足場を静止し、停止ラベルと一時停止印を追加。予約資材は残り、新着は自由在庫へ。 | `ui_pause` |
| 段階5・開発完了 | 5 | 完成段階画。新計画は表示しない。店舗/配送班の増設は上限内で継続可能。 | `ui_check` |

足場は次段階1に小、2・3に中、4・5に大を使う。足場3枚は地区原画と同じキャンバス・基準点を持ち、店舗の予約領域を覆わない。停止中も同じ足場を使い、停止印と文字を足す。段階5には足場を出さない。住宅地を未開通にしない。

| 設備状態 | 表示 | 共通資材 |
|---|---|---|
| 購入できる | 通常の絵＋費用・実購入数・前後の能力と主ボタン。 | 専用画像なし（DOM） |
| コイン/資材が不足 | 絵は読めるまま。足りない通貨と数量を示す。 | `ui_info` |
| 段階・開通条件待ち | 未達条件を項目ごとに示す。薄色だけで意味を伝えない。 | `ui_lock` |
| 現在の上限 | 段階別上限なら次段階の条件、最終上限なら上限到達と表示。 | `ui_check` |
| 配達/練習の終了後に変更 | 停止中を含む実行セッションでは購入と計画操作不可。終了後に確認して購入する。 | `ui_pause` |

理由の優先順はセッション実行中→現在の上限→前提条件不足→資源不足→購入可能とする。すべての必要条件は詳細に並べ、段階上限と全体上限の次の行動を区別する。鉄道化した路線では道路車両を貨物列車へ置き換え、班数の節目は数値と小さな節目印で保持する。

状態更新と保存は演出より先に確定する。50msの保持は満載時の荷物の絵だけに適用し、タイマー・文字入力・次の語を止めない。独立した動画やコマ画像は0点で、同じ原画とCSS/SVGの変化から作る。入力中の実績通知は既定で無音とする。

## 8 制作後の検収

| 検収 | 合格条件 |
|---|---|
| 系統内の6切手 | 72pxで主役の輪郭と配置を区別できる。数字や色だけの差にしない |
| 地区0〜5 | 96×72pxで前段階からの主役・高さ・配置の変化を読める |
| 同じ地区を3景観で合成 | 店舗・桟橋・貨物場・路線に浮きや食い込みがない |
| 設備の各外観帯 | 荷づくり5種、道路4車種、店の追加3部品が縮小で分かる |
| 通常/箔押し台紙 | 共通箔の輪郭が静止状態で読め、6切手を隠さない |
| 未解除/仮達成/獲得 | 彩色だけで区別せず、名称と状態ラベルを読める |
| 選択/ピン/未読/装着 | 同時表示でもそれぞれの意味と位置を取り違えない |
| 動き軽減 | 同じ成果と操作可能時点を静止表示で伝える |
| 数値・日本語 | 画像への焼き込みなし。200%拡大で情報と操作を失わない |
| 出力データ | 寸法・透過・基準点・形式・IDが台帳と一致する |

これらは制作後の合格条件であり、未制作の個別原画に対する実測結果ではない。今回の機械検査の結果は[資材検証報告](resource_validation_report.md)に分ける。

## 設計根拠

sakurai-skillのui #252は`多すぎるとごちゃつく`と記す。実績や設備の全状態を計測しても、プレイ中の表示は入力と配達判断を優先する。状態は小さな共通部品と文字へ分け、画面を重ね物で埋めない。[出典](https://github.com/kociden/sakurai-skill/blob/913dc46b9dedc5e0b12e3834d25d684cf8213f87/references/ui.md)。
