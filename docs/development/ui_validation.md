# UIの表示検証

## 実行

初回に依存パッケージと検証用ブラウザーを準備する。

```sh
npm ci
npx playwright install chromium
```

UIを変更したら次を実行する。型チェックと配布用ビルドの後、生成した静的ファイルを検証する。

```sh
npm run check:ui
```

既にあるChromiumを使用する場合は、環境変数 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` に実行ファイルの絶対パスを設定する。配布済みファイルのみを再検証する場合は `node scripts/check-ui-layout.mjs`、文字倍率を限定する場合は `--scale=1.3` を指定できる。

## 対象

10インチiPad横向き相当の1180×820、タッチ対応Chromiumで、文字倍率1.0・1.15・1.3を確認する。実機iPad・Safariの検証は別途行う。

| 画面・操作 | 確認内容 |
|---|---|
| 初回の目的ダイアログ | イラストの大きさ、文字、ボタンとフォーカス枠 |
| 開始前の確認 | 入力欄のないFキー表示、3・2・1の順序、待機中の入力が成績に混ざらないこと |
| チュートリアルの入力 | 入力部分の背景が暗くならないこと |
| 通常便と追加便 | 5つの印の点灯、通常便との同時発送、ノーミスの6問目以降の追加便と貨車、誤打後の消灯と積み荷の保持 |
| 荷物の積み込み | 満載時に5個目が一番上の包みの中心へ着く場面と、その後の出発 |
| 設定 | 配達キー設定を除いた画面の文字、ボタンとフォーカス枠 |
| 切手3枚の獲得 | 登場演出中、操作待ち、次へにフォーカスした状態の表示領域 |
| 配達資材の受取・街づくり案内 | ダイアログ、吹き出し、住宅地・荷づくり台の操作 |
| チュートリアル完了 | 背景を暗くするダイアログ、ホームへ戻った時の切手3枚 |
| メインメニュー | H・J・K・L・Sの移動、未読数と各タブのフォーカス枠 |
| 配達手帳 | 切手の詳細と閉じる操作 |
| 通常の街づくり | 地区の発展で解除した切手が直ちに表示されること |
| 通常の配達開始 | カウント終了後に90秒の時計が進み始めること |

通常の街づくりと通常の配達開始は文字倍率1.3で実行する。

## 検出方法

`scripts/ui-bounds.mjs` が文字の描画領域、画像、操作部品、フォーカス枠の幅と外側の余白を計測し、画面と切り抜きのある親要素の内側に収まるか確認する。ボタンやキー表示の文字が自身の枠内にあるかも調べる。操作部品の中央と両隅を調べ、別の要素に覆われていないか確認する。ダイアログはブラウザーの最前面表示に対応し、背面要素の切り抜きとは分けて判定する。

ダイアログ表示中は描画フレームごとに計測し、演出中の異常も記録する。キーボード操作時は各部品へフォーカスを移して検査する。許容する座標の丸め誤差は0.75px。

検査の開始時に、フォーカス枠の欠け、文字の切り抜き、ボタン外への文字のはみ出し、操作部品の重なりを意図的に作った小さな画面を検査し、検出器自体が異常を捉えることを確認する。スクロール幅が正常でも外側のフォーカス枠は欠けるため、スクロール幅の一致だけでは合格にしない。

画面・操作を追加した場合は `scripts/check-ui-layout.mjs` の対象にも加える。視覚的な分かりやすさ、音、操作意図の伝わり方は独立したE2Eレビューで確認する。

## 出力

`.codex-temp/ui-layout/report.json` に対象画面、描画フレーム数、異常の種類と欠けた量、ブラウザー例外を保存する。同じフォルダーに各画面の画像を保存する。異常を検出すると終了コードを失敗にする。

`UI_LAYOUT_OUTPUT` で出力先を変更できる。指定先はプロジェクト内の `.codex-temp/` 以下に限定する。
