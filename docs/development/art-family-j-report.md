# J系統切手 — 制作候補報告

対象は `stamp_j01`〜`stamp_j06`。AGENTS.md、制作資料入口、正本マニフェストの6件、実績カタログの図柄・識別点、design_tokens、rendering_rules、資材実装仕様のstamp契約を読み、5代表画面と既存F01・I05の原画を目視参照した。クリーム、森林緑、黄土、赤茶の水彩・ガッシュ画風で制作した。共有台帳・レジストリ・UI・仕様は変更していない。

## 生成と由来

実際のimagegenで6件の新規生成とJ01の画像編集を実行した。最初の6件並列要求は、ひとつの出力が安全システムでviolenceと判定され、結果返却前に呼び出し全体が終了した。どのIDの出力判定かは特定できず、返却画像はなかった。同じ無害な物流モチーフのプロンプトを個別失敗が他を終了させない方法で再要求し、6件を取得した。正確なプロンプト・透過指定・返却原生パスは `production/family-j/requests.json`、失敗と不採用記録は `rejects.json` に保存した。

J01の最初の返却画像は1536×1024だった。ビューアで茶色のにじみが見えたため背景除去と正方形化のimagegen編集を行ったが、その後のアルファ検査と不透明な紙色への合成で、茶色はalpha 0下の隠れたRGBの表示による誤認と確認した（上中央の標本はRGBA 47,36,19,0）。実際の茶色背景欠陥はなかった。原生・編集の両方と紙色合成の確認画像を無変更で保持し、正方形の編集結果を制作候補に選んだ。欠陥を隠すアルファ閾値・マスク・切り抜きは行っていない。

返却原生は `production/family-j/stamp_jNN.attempt-02.png`、J01編集は `stamp_j01.attempt-03.png`。選んだ原生1254×1254 RGBAの無変更コピーは `public/assets/originals/stamp_jNN.generated.png`。全返却ファイルのSHA256を `native-file-hashes.json` に記録した。

## 書き出しと単体検査

`production/family-j/export.py` で原生キャンバス全体を448×448（倍率448/1254）へ等方縮小し、512×512透過キャンバスの(32,32)へ配置した。トリミング、アルファ閾値処理、マスク、手描き補正はない。`stamp_jNN.normalized.png` と同内容の指定PNG `stamp_jNN.png`、正規パス `public/assets/achievement_stamp/stamp_jNN.webp` のlossless WebPを書き出した。

6件とも512×512 RGBA、論理アンカー(256,256)、全出力アルファ境界が安全域32..480内。PNG/WebPのアルファ全画素および紙色合成全画素一致を検査した。`measurements.json` に原生・正規化PNG・WebPのSHA256、サイズ、バイト数、境界、正確な変換を保存した。原生の低アルファ粒子にはキャンバス端へ接するものがあり、出力安全域検査だけで生成器内の未切断まで保証しない。
