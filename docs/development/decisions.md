# 判断記録

## D001: 正本と段階開発

元の仕様は改変せず、TypeScript/DOMの静的アプリでM0/M1を最初のサイクルとする。全仕様完成を初回の終了条件としない。目標そのものは維持する。

## D002: 正確な算術

価格・経済はPython参照と同じ整数/有理数を使用。得点は10L、配達はfloor(Vn/5)。誤打した語も完成点は10Lで、未配達ボーナスだけを失う。経済倍率はタイピング得点へ掛けない。

## D003: 公開先変更

ユーザーの後続指示「Pages → ChatGPT Sites」に従いGitHub Pagesは使用しない。GitHubはpublicなソース管理、実行するSiteはオーナー限定。Sites project_idは `.openai/hosting.json` に固定し、同じSiteを更新する。閲覧者の追加や公開範囲拡大をしない。

## D004: 検証範囲

960語の正本検査やLinux Chromium自動試験は、Windows/macOSのOS IME・JIS/US物理キーボード・初見観察を代替しない。M6まで未検証項目を明示する。

## D005: 作業担当

入力/画面/経済/記録/アート/独立QAを別worktreeへ分担。統括が設定・進捗・統合・公開を担当。変更は小さな機能コミットとPRで保存する。

## D006: Sitesソース同期

この実行環境にはSitesパッケージのsource helperスクリプトが存在しなかったため、同じSiteの短期資格情報をecho無効のstdinで受け、メモリー上のGit HTTPヘッダーとしてのみ使用してSite専用リモートへ通常pushした。資格情報をファイル・Git設定・コマンド引数へ保存していない。pushしたHEADからViteをビルドし、hosting.jsonとdistのみのtar.gzをnative private deployへ渡した。次回はhelperが利用可能なら正式helperを使う。

## D009: 所有権引継ぎ時の便の終了

技術仕様16.8の所有権喪失ではPAUSEDへ移し、7.2の途中終了確認を満たしてから別タブの最新状態へ切り替える。進行便がある「ここで続ける」は終了確認を挟み、取消では元のPAUSEDを維持する。確認後は途中終了事実を一度発行してHOMEへ戻し、新しい便IDで開始する。別タブで閉じた経済セッションへ、古いGameSessionを無言で再接続しない。

明示的な未保存破棄では、控えに元投影を保持し、古い便の閉鎖事実はカーソルだけを進める。捨てた語/配達を再生して集計を復活させず、閉鎖事実の順序欠落も起こさない。通常の同じ所有者による停止/再開は従来通り元セッションを保つ。初期仕様は書き換えない。

## D010: 街データの不正とオフライン時計

街は専用schema1.0.0でmicro値を10進文字列として保存し、DBから読む境界で検証する。不正な街は控えに元データを保持し、プロフィールを保ったshadow memoryの街で続ける。元DBを初期化して上書きしない。オンラインは固定した単調時計の起点から整数msの絶対時刻を計算し、資源と壁時計基準を同じ更新で保存。復帰は最新保存基準から8時間までを一度適用する。描画tickや通知の完了は資源の発生源ではない。

## D011: 公開物と原画

生成原画・正規化PNG・不合格候補はGitのsourceに保持する。本番配布tarでは未使用のdist/assets/originalsを除き、実際に参照するWebP/SVGとビルドJS/CSSを配布する。原画を消さずに配布サイズを抑える。

## D012: 旧版互換性を要件から除外（2026-11-14 Asia/Tokyo）

ユーザーの明示指示「旧版データなどというものはないです。過去互換性は一切無視してください」を適用する。初期仕様10.3/16.8にある旧localStorage・旧IDBからの移行、旧形式・旧報酬キーの互換処理は対象外とし、未達成項目や阻害要因へ数えない。初期仕様の保存原本は改変しない。

現行形式の検証・バックアップ復元、同時更新・所有権・削除世代・原子保存は引き続き製品要件とする。不正なデータを無言で上書きしない保護も維持する。存在しない旧形式を推測して実装しない。

## D013: 指定iPadとキーボード操作（2026-11-14 Asia/Tokyo）

最新mainのAGENTS.md（31f528e）を取り込み、「10インチiPad横向き（MM9C3J/A）」を主な表示テスト対象とする。ユーザーの追加指示により、スクロールなしで必要情報と操作へ到達でき、マウス・タッチなしで画面移動できることを受入条件とする。1180×820 CSS pxと、ブラウザー操作領域を考慮した1180×720で検証し、実機Safariの確認とは区別する。一覧・設定はページやパネルへ分け、下部を隠すだけでは合格としない。ローマ字・配達キーと画面移動を干渉させない。

節目では、会話履歴を継承しない独立エージェントへ、評価資料としてsakurai-skillだけを渡してE2Eレビューを依頼する。

2026-11-14の追加ユーザー指示により、sakurai-skillレビューの各指摘は「観察事実→skillの短い引用と正確な参照箇所→当該問題との因果的な関連→具体的修正案」を必須とする。skill自体の記載とレビュアーの解釈を区別し、動画番号を添えるだけの指摘や、関連を説明できない一般論をsakurai-skillの所見へ含めない。既存レビューもこの形式で改訂する。

さらに、キャプチャだけの確認による代替をユーザーが明示的に不許可とした。以後はレビュアー自身のシナリオを実ブラウザーE2Eで実行する。共有ブラウザーの基盤障害がある場合も、実Chromiumが動くCIでシナリオを実行し、その操作と検証結果に基づいてレビューする。画像は補助資料のみ。第3サイクルの画像観察記録は参考であり、独立E2Eレビューを完了した根拠へ数えない。

## D014: ゲームステージ・地区マップ・個別報酬演出（2026-11-14）
ユーザー追記を受け、M4のページ分割による画面内表示だけでは完成としない。主要画面をゲームのステージ/HUDへ再構成する。全体マップ→地区全域の拡大マップを連続させ、発展/建設/各設備の実状態をそのマップへ描画する。90秒終了時は独立した結果ステージで、今回確定した実績を一枚ずつ演出する。実績付与・資産消費は既存の原子的処理を維持し、演出中の重複付与や架空抽選を作らない。画面内配置、すべてのキーボード操作、実状態と描画の対応は実ブラウザーE2Eで受け入れる。M4は実績/入力/保存の基盤として統合済みだが、この追加要求の受入完了を意味しない。
