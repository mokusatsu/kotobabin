# 川沿い地形の再診断と実生成修正

対象は既存ID `terrain_riverside` のみ。専用worktree `/workspace/work/riverside-m6`、branch `task/riverside-m6` で制作し、rootの作業ファイル、UI、正本、共有台帳、他景観は編集していない。AGENTS.md、地形プロファイルとbrief、共有12点、港接点、18map_px離隔、全6経路の24map_px保護域を読み直した。画像生成後の岸線マスク、色閾値による画像改変、切り抜き、岸線への手続き的な当てはめは行っていない。

## 実制作と採用候補

実imagegenを4回実行した。変更前の原画・native・WebPを `public/assets/originals/production/riverside-fix-m6/history/` に未変更で保存し、hashを検証した。全4回の未変更nativeは `native/r1.png`〜`r4.png`、正確なプロンプト・参照・成否は `requests.json` にある。失敗を消して成功だけ数えていない。

1. 正本3200×2000座標ガイドと既存画風を参照。港離隔21.5だが岸線最大差3.7273で悪化し、不採用。
2. 上記候補の岸線だけを戻す実編集。港離隔19.5だが最大差2.9043で現行より悪く、不採用。
3. 正本ガイドだけを固定形状のテクスチャ化に使用。最大差0.8717へ改善したが、PNGの港離隔17.5が残ったため後続修正へ。
4. 港の垂直岸線付近で陸側にはみ出す薄い青縁だけをimagegenで限定修正。PNGの港離隔18.0、全行最大差0.8636となった。この **r4を改善候補として採用**。

制御ガイドは正本12頂点から作った診断・生成参照図であり、最終画像へ合成せず、runtimeの代替画像にもしていない。r4の実nativeは **1585×992 RGB**。全キャンバスを3200×2000 RGBへ正規化したPNG masterと、既存runtimeと同じ **WebP quality92/method6** を納品した。実nativeを3200×2000で生成したとは記載しない。横倍率3200/1585、縦倍率2000/992で、nativeの8:5比との差は−0.13860887%。全キャンバスを保持し、切り抜き・移動・部分変形・背景補塗りはしていない。

runtimeは233,406bytes（以前406,786bytes）。可逆WebPも制作フォルダへ保存してPNGとのRGB全画素一致を検証した。runtimeのquality92は品質を走査して閾値が通るものを選んだのではなく、従来の符号化条件を継続したもの。native/master/runtimeのサイズ・SHA・変換は `selected-export.json` に記録した。

最小800×500で変更前後、色・グレー、正本岸線・6経路・荷下ろし矩形の診断重ねを目視した。淡い紙色の平地、外周左の丸い木、左上の低い山、右側の穏やかな水域を維持し、中央・地区・経路の空きを塞いでいない。木の配置や水彩の細部は新しい生成に伴い変化した。建物・路線・港・文字は地形へ焼き込んでいない。

修正済み港stage5を正規の(1058,570)・264×198で重ねた静止診断も保存した。これは別途制作済みの港画像を使うQA合成であり、runtime地形に建物を加えたものでも実ブラウザーのE2Eでもない。参照元とSHAは `composition-reference.json` にある。
